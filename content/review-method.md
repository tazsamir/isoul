description: "How a new project moves from interesting to recommended."
---

Automation may find a project, but it cannot decide whether it belongs on this site.

## Checklist

Before recommending anything, check:

- Official project website and source repository
- Clear open-source licence
- At least six months of meaningful maintenance where possible
- More than a single initial release
- Documentation that explains installation and recovery
- Issues and pull requests receiving reasonable responses
- Data export or standard formats
- Backup and restore instructions
- Security history and release process
- Resource requirements and update risk
- A real test, or an honest statement that it has not been tested

## Statuses

**Watching** means interesting but unproven. **Worth testing** means it has passed a basic review but has not yet earned a recommendation. **Recommended** means it has been tested or examined carefully enough for normal use. **Rejected** means there is a reason not to recommend it currently.

A project's GitHub stars are not a validation method. Popularity helps discovery, but it does not prove quality, safety, maintenance or suitability.

## Automation rule

A scheduled collector may create a draft candidate or pull request. It must not publish an article or silently change a recommendation. Every published review requires a human decision recorded in Git.
